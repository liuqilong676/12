# 需求说明：校园物联网设备报修

## 1. 角色与范围

| 角色 | 说明 | 职责 |
| --- | --- | --- |
| 报修人 | 实验室与教学楼设备的使用者（学生、教师、值班人员） | 查看设备信息、选择清单内设备提交故障报修 |
| 维修人员 | 后勤保障或实验室技术人员 | 查看设备信息、受理待处理工单（开始维修）、维修结束后完成工单 |

系统边界：只覆盖“查看设备、提交报修、更新工单状态”三项功能。设备数据取自起始包中的
模拟清单 `data/devices.csv`（温湿度传感器 `DEV-001`、智能门锁 `DEV-002`、
烟雾传感器 `DEV-003`），不接入真实传感器数据，不实现登录、数据库、网页和 MQTT。

统一状态名称：待处理 `PENDING`、处理中 `PROCESSING`、已完成 `COMPLETED`。新工单为
`PENDING`；仅允许 `PENDING → PROCESSING`、`PROCESSING → COMPLETED`；跳级、回退、
状态不变及其他转换一律拒绝。`COMPLETED` 为本次业务终态，不设重新打开与撤销。

## 2. FR-01 查看设备信息

- **角色**：报修人、维修人员
- **前提**：系统已成功加载 `data/devices.csv`，清单至少含 1 台设备。
- **输入**：设备编号（如 `DEV-001`）；不输入编号时返回全部设备。
- **正常结果**：显示设备的 `deviceId`、`name`、`location` 三项；全部设备按编号升序返回，
  保证同一清单在不同机器上显示顺序一致。
- **异常结果**：编号不在清单内（如 `DEV-999`）时提示“设备编号不存在：DEV-999”，
  不返回任何设备信息，程序不异常退出。
- **验收条件**：
  1. `list_devices()` 返回 3 台设备，编号顺序为 `DEV-001`、`DEV-002`、`DEV-003`；
  2. `get_device("DEV-002")` 返回名称“智能门锁”、位置“B202实验室”；
  3. `get_device("DEV-999")` 抛出 `DeviceNotFoundError`，异常信息包含该编号。

## 3. FR-02 提交报修

- **角色**：报修人
- **前提与输入**：设备编号必须存在于清单；故障描述必须非空（去除首尾空白后仍非空）；
  报修人可省略，省略时记为“报修人”。
- **正常结果**：生成一张工单，`orderId` 形如 `WO-20261110-001`，`status` 为 `PENDING`，
  记录设备编号、故障描述、报修人与创建时间；工单总数加 1。
- **异常结果**：
  1. 设备编号不存在 → 抛出 `DeviceNotFoundError`，**不创建工单**；
  2. 故障描述为空、全空格或全换行 → 抛出 `ValidationError`（提示“故障描述不能为空”），
     **不创建工单**。
- **验收条件**：
  1. 正常提交后 `list_orders()` 长度为 1，且该工单状态为 `PENDING`；
  2. 三种空白描述分别提交后，`list_orders()` 仍为空；
  3. 使用不存在的设备编号提交后，`list_orders()` 仍为空；
  4. 描述 `"  门锁无法刷开  "` 保存后为 `"门锁无法刷开"`（首尾空白被去除）。

## 4. FR-03 更新工单状态

- **角色**：维修人员
- **前提**：工单编号存在。
- **允许的转换**：`PENDING → PROCESSING`（开始维修）、`PROCESSING → COMPLETED`（完成维修）。
- **拒绝的转换**：`PENDING → COMPLETED`（跳级）、`COMPLETED → PROCESSING`（回退）、
  `COMPLETED → PENDING`、任何状态不变、未知状态值、大小写不符（`pending`）、`None`。
- **正常结果**：工单状态更新并记录维修人员；开始维修写入 `started_at`，完成维修写入
  `completed_at`。
- **异常结果**：被拒绝时抛出 `InvalidTransitionError`，工单状态保持原，其他字段不被修改，
  不产生“半更新”的中间状态。
- **验收条件**：
  1. 规定 4 项测试 T01–T04 全部 PASS（见 `docs/test-results.md`）；
  2. 跳级（PENDING→COMPLETED）被拒绝后，工单仍为 `PENDING`；
  3. 完成维修后再次开始维修被拒绝，工单仍为 `COMPLETED`；
  4. 对同一工单重复“开始维修”被拒绝。

## 5. 已确认的实验规则（全体统一）

新工单为 `PENDING`；仅允许 `PENDING → PROCESSING`、`PROCESSING → COMPLETED`，其余转换
一律拒绝，包括状态不变。本实验只实现状态判断函数与三项需求的业务校验，不实现完整报修
应用、登录、数据库、网页或 MQTT；起始函数未实现时规定测试应为 2 项 PASS、2 项 FAIL。
